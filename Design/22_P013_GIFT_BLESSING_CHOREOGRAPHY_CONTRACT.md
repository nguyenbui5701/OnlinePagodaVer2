## 2. Scope boundary — P0.13-A, not a new content/asset stage

### Included: one isolated gift blessing visualization

- For validated **observed** gift: retain a **short, subtle provisional** warm ring/limited sparks, not a confirmed rose celebration or falsely counted gift.
- For validated **confirmed** gift and correct **current actor/seat**: one deterministic, staged **localized** sequence under the actor's P02 pad:
  - (a) **0–~220ms** warm near-pad pulse with restrained gold/rose tint, no global exposure flash;
  - (b) **~180–1100ms** **three to five abstract, original luminous petal/orb halos** orbit/rise around the body, safely below/alongside the face and away from nameplate. **These are FX shader particles built from simple curves/points, not user-licensed rose ICONS.** They do **not** purport to reproduce bespoke reference rose imagery; their count is **pure decorative timing**, never equal to `giftCount` or money;
  - (c) **~650–1350ms** a bounded spark trail/gradient drifts *toward* Sakura from the true gift anchor and optionally applies a small localized/gold-vein pulse through existing **renderer-owned cloned material**, without changing the underlying source GLB, global P0.11 look preset or sky/fog;
  - (d) **~1350–1650ms** all new effects recede naturally; **on CINE_RETURN**, existing camera route continues untouched; on next actor B/C, new FX binds exclusively to that current actor and old spatial effects end/fade safely.
- Optional **original, fixed, sanitized short blessing line** (e.g. “Chúc bình an”) only in confirmed focus, inside 9:16 safe margins, not derived from raw chat/comment or untrusted nickname. Treat as subordinate to existing true `An` and `2 hoa hồng` UI labels. If it blocks face/name in any evidence shot, omit it instead of relocating other UI.
- ECO and QUALITY use the **same semantic sequence** with distinct conservative counts/brightness. Existing `giftTiming` and FIFO/camera durations are source authority; visual subphase durations above are **tunable proposals**, not independently proven exact video timing.

## 3. Binding and event semantics — invariants

1. **Do not implement a second scheduler.** Use one authoritative `GiftFxLifecycle.update(state, ack, binding)` to emit existing `gift` with `roomSessionId`, `requestId`, `actorId`, `seatId`, `phase`, `startedAtMs`, `expiresAtMs`, `progress` and `opacity`. Derive all new subphase intensities from this verified cue and existing `state.atMs`, **not wall clock randomness**. Do not store another unbounded replay cache or count gift commerce.
2. **Actor focus:** Only the `ActorTarget` matched to the true `AvatarPresentation` and active intent/ack owns world FX. Read `seat.fx`, `seat.seatRoot`, `seat.head`, tree root world coordinates; never infer user gender, seat, name, giftId or model from the anonymous figures, gifts or display name. Name plate/FX anchors must work for P05f and P07b1.
3. **Late, duplicate, provisional and invalid:** observed is not confirmed; repeated final/ack does not re-trigger or reset choreography; out-of-capacity Duyên, stale room epoch, reconnect duplicate, expired FocusIntent, missing actor, no-seat/overlay fallback produce **zero spatial choreography**. Return/interrupt clears/shortens old cue; B/C must not inherit A's rings. Room change and disconnect reset visible FX and do not replay old confirmed cue.
4. **Label and camera safety:** 720×1280, existing `capture.safeMargin=.08`; no face/name/gift overlap and no large foreground splash hiding P05f palms or clothing. Fixed 3 authentic seats remain the only spatial targets. No change to `packages/v2-events/**`, `camera.ts`, `slice-driver.ts`, `seat-scene.ts`, GLB or baseline cinematics unless an independently proven P0.13 integration bug cannot be fixed in isolated FX modules.
5. **Determinism:** same exact snapshot stream, `seed`, profile, virtual clock, actor/seat and gift state must yield repeatable positions, color, fade values and WebGL frame images independent of real clock, event duplicate delivery and client reload. No per-frame allocations of meshes/materials/textures or per-gift new large buffers.
6. **Feature safety:** NEW documented `?blessing=off|on` switch, default **OFF** until Owner P0.13 Visual GO. It is active only for synthetic `demo=gifts`, `demo=capacity`, `demo=community` when `fx` is not `off`; legacy `demo=idle` and `?fx=off` remain unchanged. With `?blessing=off`, **pixel-identical PR #12** screenshots at exactly matched state/camera/time is required; no new artifact load or altered normal look.
7. **Resource lifetime:** size of particles, geometry, materials, tracked cues and glow objects is bounded. Frame after context-loss/restore must have no normal WebGL errors, gift, actor and label still correctly bound; known synthetic teardown invalid-delete warnings must be attributed and not called normal-pass “zero warnings.”

## 4. Implementation design and bounded profile budget

- Prefer **one new `gift-blessing.ts` pure subphase planner** (table of curves/progress/actor binding and output alpha/scale), **one minimal gift-FX visualization extension** (existing Points/ShaderMaterial capacity, optional one additional pooled Points/gradient), and **`main.ts` wiring** limited to adding approved FX and showing fixed blessing text when permitted.
- If gold-vein response is used, apply **base P0.11 multiplier `appearance.veinEmissive` × bounded cue envelope** to the existing `gold.update` each frame, never overwrite its baseline or clone a second Sakura material; when disabled or after cue return it must resolve exactly to base. Do not touch source `lighting.ts` unless a shared typed hook is essential and explicitly justified by tests.
- **Initial ECO:** 3 decorative halo orbs, small extra trail; **QUALITY:** 5 halo orbs, modest extra sparks; choose fixed upper bound in named `fxProfiles` config with measured emissions. Aim at **≤+3 draw calls ECO / ≤+5 QUALITY** during active gift vs P0.12-D, without sacrificing correctness; if achieved costs differ, report objectively and explain, never misrepresent it as a hardware FPS PASS.
- Prefer additive transparency with depth check to avoid drawing through character; use original approved colors under P0.11 lighting with bounded luminance/opacity. Avoid full-screen post-processing or screen-space bloom pass. Tree streak should never look like a beam incorrectly emanating from another seat.
