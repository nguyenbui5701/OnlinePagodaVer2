## 3. Architectural invariants and upgrade tracks

1. **Domain authority:** only \`DemoEngine\`/future approved real provider mapping owns session, \`actorId\`, \`seatId\`, \`confirmedGiftCount\`, and FIFO \`FocusIntent\`. The renderer consumes \`AvatarPresentation\` only; no real participant is invented by decorative seating or a screen-name bubble.
2. **Seat truth:** Existing accepted total **12 visual positions**, **3 authoritative seat-capable actors**, **9 anonymous decorative figures**. The initial RINGS mode must still have **exactly 12 physical pad locations and stable original 3 seat IDs**; it may rearrange transforms under a feature flag but may not change the engine's 3-person cap. When a fourth real user arrives, do not secretly seat them in a decorative slot, display a fake count, or steal another seat. A later **expanded real-seat-capacity design/gate** is required if Owner elects more than three real seated viewers; rings designed with future expansion in mind but no automatic 12 real viewers.
3. **True/live versus demo:** \`source=live\` currently means **OFFLINE**. All bubble/pad UI may be validated with synthetic *unit/integration test cases* and explicit DEMO; these are not an independent CODEX 12 offline replay phase and cannot pass actual live provider access or a real live gift requirement. A live session must show OFFLINE until real provider gate passes. It must never silently fall back to demo chat/gifts.
4. **No implicit media usage:** Display only approved remote profile photos with a source-allowlist and consent/terms compatibility; require safe URL verification, private-IP/redirect defenses if a proxy is created, HTTPS-only, no referrer leakage, cap dimensions and bytes, sanitized render element; fallback to original local initials/silhouette. **Do not include screenshots or actual third-party portrait photos in GitHub artifacts**. A provider's remote avatar URL is not equivalent to permission to publish/cache it.
5. **Feature flags and staging:** new UI/FX/layout are opt-in during design QA, e.g. \`presence=on\`, \`chatbubbles=on\`, \`gifticons=on\`, \`ambience=rich\`, \`seats=rings\`, \`shots=hero\` (exact names to be implemented/documented). Default OFF/legacy must render the same PR #15 screenshots and camera, room and actor state. Do not change default LIVE status or launch mode. No new code to V1 or user-login services.
6. **Stable rendering:** world anchors must be P05f/P07b1-compatible; project to 720×1280 screen safe area, occlusion/depth/culling policy, no name/face/hands/gift text cover, gift camera is higher priority than chat; avoid layout modifications that teleport focus targets, collide with trunk/branches, crowd petals or lotus flowers.
7. **No licensed rose art bypass:** original gift-type image icons may only come from a specifically approved source, declared license and validated giftType→asset manifest. When a real provider sends an unknown gift type or unavailable image, show an **original neutral token** and truthful name/quantity; don't scrape TikTok icons or invent rose mapping. This is distinct from original P0.13 reference rose-icon art which remains deferred.

## 4. Track A — P10B3-A viewer identity, chat bubbles & gift bubbles (CODEX 14; FIRST)

**A1. Identity/name/photo**
- Reuse \`AvatarPresentation.displayName\` and \`avatarUrl?\`, seat \`NameplateAnchor\`. Add small seat-bound UI that shows **sanitized name plus authorized photo or fallback** for the three true current actors, with camera-safe culling and automatic disappearance on TTL, room change, reconnect or unavailable anchor. Do not attach photos or person data to anonymous figures.
- Name/avatar only render if valid actor/seat binding; treat \`avatarUrl?\` as **data available, photo UI not yet implemented**. In simulated screenshots use original local neutral initials, never real person's screenshot. Never infer identity/gender from name or photo.

**A2. Chat text protocol amendment**
- Existing \`DemoEvent\` chat carries no text. Require a **documented backward-compatible opt-in typed amendment** (e.g. optional \`chatText?: string\` on chat events) and a versioned \`ChatCue\`/effect carrying \`roomSessionId,eventId,actorId?,seatId?,sanitizedText,atMs\`. If wire output shape changes, **bump/route protocol version and migration tests**; do not silently claim protocol 0.1.0 already includes chat content. Scene must not directly read unvalidated provider payload or bypass Engine state/seat authority.
- Strict NFKC/NFC normalization as chosen and documented, \`Intl.Segmenter\` grapheme cap (proposed <=120 graphemes), no HTML/markup, bidi/control stripping, URL/emoji handling, reject or neutralize spam/newlines and suspicious directional chars. No raw content in public GitHub traces.
- **User not seated:** chat can appear as a small **nonspatial, rate-limited overlay** with truthful display name; no seat-bound animation/gift focus or auto-spawn unless explicitly authorized by current Engine config. If no content (legacy 0.1.0 event), do not render an empty bubble.

**A3. Bubble timing and motion**
- Provisional dwell formula **1000–2000ms** based on displayed graphemes (e.g., 1000ms + 25ms/grapheme, clamped to 2000ms; tuned from genuine 720×1280 crop). **After dwell**, transition to a smaller circular floating bubble for another **650–1100ms**, rising ~30–90 CSS px with opacity fading to zero. This is **two stages**; "1–2s" applies to readable text stage, not a claim that entire lifecycle ends in 2s.
- Anchor to true seat name/head offset, prevent face/name/camera target occlusion, cap visible strings and bubbles, coalesce or suppress spam deterministically. GIFT_FOCUS label/FX overrides or hides chat bubbles; no overlap with restricted top/bottom LIVE Studio safe zones. Pool DOM nodes or efficient elements; no per-frame unbounded allocations.
- Clear on room change, TTL/disconnect, actor removal, missing seat, source mode change and WebGL context loss/reinit. Deterministic event clock for replay tests; use real wall clock only for runtime tick, never event business ordering.

**A4. Per-gift-type bubbles**
- Separate visual \`GiftVisualCue\` from existing \`giftFx\` event with \`giftId,giftCount,confirmation,roomSessionId,requestId,actorId?,seatId?,atMs\`. Use existing \`GiftFxLifecycle\` to guarantee one transition for each confirmed phase and no duplicate/reconnect/replay bubbles. \`progress\` may show a subtle provisional indicator but **no final gift icon/count until confirmed**.
- Choose icon from an **allowlisted original/approved gift visual manifest** keyed to normalized gift ID; unknown type uses a neutral original symbol with truthful text. Do not copy rose-badge from screenshots or require paid proprietary third-party artwork. Cap around **3 ECO / 5 QUALITY visible type bubbles simultaneously** initially, regardless of cumulative giftCount; orbit/rise/fade approx 0.9–1.8s and never change domain gift quantity.
- Unseated fourth giver gets original truthful text-only fallback, **no spatial gift bubbles**. Gift FIFO A→B→C, camera target and original blessing shader unchanged when flag OFF.

**A acceptance:** old 47 baseline tests (PR #15 reported 8 Event +39 Viewer) + new typed sanitizer/migration tests; room/actor/seat membership, 120 grapheme, time boundary 1s/2s, float transform, double-final/no-spawn, no-seat, security, photo fallback, lifecycle cleanup.
