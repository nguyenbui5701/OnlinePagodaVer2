## 2. Two independent operational paths — both for a REAL LIVE-ready product

### A. Broadcast video output (owner-operated, immediate path)

- Existing Viewer runs at `http://127.0.0.1:<port>/?demo=community&seed=9&profile=eco|quality&look=twilight&clean=1&botanicals=on&diversity=on&blessing=on`. This **currently plays DEMO gifts**, not real events. A scene window can be captured in TikTok LIVE Studio through **Window Capture** / compatible source for the Owner's eligible account, with portrait 9:16 canvas. Owner—not Codex/assistant—signs into Studio and controls preview/Go LIVE/Stop.
- Codex must deliver a runbook and prove actual local Viewer output + captured canvas at 720×1280, source/profiles/Sakura render, no browser chrome or exposed debugging/identifiers. **Never auto-click LIVE/Go Live or stream to unknown accounts/RTMP, never request cookies or account credentials**. Do not claim success if Studio/capture account/permissions are unavailable; `STUDIO_CAPTURE_OWNER_EVIDENCE_REQUIRED`.
- For real event mode, switch off demo script events and select only a validated real gateway. An actual production build **cannot silently fall back to simulated gifts while labeled LIVE**; show fail-closed **OFFLINE / CONNECTING / DISCONNECTED / EVENT_LAG** operator status distinct from video capture status. Camera returns to cinematic on valid no-gift; on connection loss clear stale focus as dictated by session scope.

### B. Real event-source worker and typed local gateway

- **Codex inspects and validates at least one genuine, Owner-permitted source**: official authorized supplier where available; existing V1 working connector if source verified; or an explicitly owner-approved, permitted unofficial receiver whose exact license, external sign service, pricing/privacy, version and reproducible read-only connection to the Owner's own LIVE room are documented. **Do not bypass platform access, paywall, CAPTCHA, anti-bot, rate limits or auth; no extracting session cookies.** If no acceptable accessible source, gate `P10B2_PROVIDER_ACCESS_BLOCKED` and deliver a working Studio capture path + read-only bridge without asserting live gifts.
- The upstream worker (separate Node process, not browser JS) may use outbound-only authorized access to LIVE and forward a **strictly bounded, normalized event stream** through an authenticated **127.0.0.1-only** local channel. No public port, remote HTTP API, open CORS, unauthenticated WebSocket, user-controlled relay destination, browser-shipped API key or paid signing service without Owner approval. Prefer an ephemeral locally generated secret used only by the operator worker/Viewer handshake, never in URLs/logs/commits; test hostile Origin and unauthenticated connections. If this protection is unworkable with a browser page, use a local-only short-lived session exchange with strict Origin, no persistent auth on client.
- Only **one domain Event Engine** owns actors, seats, session epochs and gift focus. Do not add a second scheduler. Normalize real provider events to current typed `DemoEvent | SessionEvent` `0.1.0`, validating unknown payloads/byte size/rates/user key/name/amount/eventId; adapt only genuine existing fields. **Never generate arbitrary authoritative gift confirmations, names or counts** and never interpret `repeatCount` cumulative vs incremental without source documentation and an actual observed example. 
- A **real room/session** changes roomEpoch and reconnect connection and must reject previous room/epoch stale packets; stable per-event and per-streak dedup across connection retries. User IDs must be scoped to room, normalized or pseudonymized. Raw user data not written to Github evidence. `member/chat/like/room/gift` semantics remain existing `DemoEngine`-owned; the only three real seats are from the engine. Existing `spawnOnMember=false` on the current default must not silently turn into automatic seating without separate Owner design signoff.
- Backpressure/abuse: buffer caps per room, cooldown and bounded effect updates, drop/aggregate likes/chat under load but **never silently duplicate/drop confirmed gifts**; if a gift cannot be processed, record a bounded nonpersonal error and show operator degradation, not a fake confirmed response. No arbitrary cross-site avatars or HTML, existing `displayName` sanitization and HTTPS avatar constraints retained. Avoid storing raw comments, user IDs or secret room metadata in evidence.
- Viewer isolation: `source=live` (or equivalent explicit operator command), only via authenticated local worker and explicit operator action. `source=demo` continues unchanged; no real provider initialized in demo state. **No public browser source URL** with secrets; safe capture preview should hide internal warnings from viewers. Server-side status panel must distinguish `CONNECTED/NO_EVENTS` vs `CONNECTED/EVENTS_VERIFIED`; absence of gifts during an actual stream is not evidence gift handling works.
