## 2. Architecture and strict responsibility boundary

**P1.0-B1 offline pipeline:** 

`synthetic immutable fixture file (versioned JSONL/JSON)` → `untrusted-shape parser/validator + size/rate caps` → `normalize to DemoEvent | SessionEvent (protocol 0.1.0)` → `existing DemoEngine.ingest/advance` → `Snapshot + Effects` → `existing SceneObserver/seat world mapping/giftFx/camera` → `existing Three.js Viewer 3D`.

- Keep domain authority **only** in `DemoEngine`; transport-normalization never creates `FocusIntent`, actual seat assignment, `confirmedGiftCount`, `actorId` or arbitrary `CameraPresentation` itself.
- Keep original P0.9/P0.10/P0.11/P0.12/P0.13 visuals identical for the old `?demo=idle|gifts|capacity|community` path unless a clearly reviewed, opt-in `?source=replay` is selected. **No new real users:** 12 original visual positions = 3 actual DEMO-capable seats and 9 anonymous decorations. Never create twelve authoritative viewers.
- **Proposed bridge code ownership:** new isolated `packages/v2-events/src/offline-replay.ts` or `packages/v2-replay/**` source + tests, and a small `apps/v2-viewer/src/replay-driver.ts` + minimal `src/main.ts` source selection. Keep `focus.ts`, `registry.ts`, `camera.ts`, accepted model materials/geometry, `slice-driver.ts` original fixtures as functionally frozen unless a proven shared interface extraction is required.
- Source selection: **DEV-only and loopback-only** `?source=replay` or documented equivalent. Require `import.meta.env.DEV` and `location.hostname ∈ {127.0.0.1,localhost}`; no external network fetch, no local backend WebSocket, no implicit remote URL, no operator credential prompts, no real LIVE. A built production app must **hard-disable replay mode** or fall back safely to the previous normal DEMO with explicit diagnostic.
- Fixture input is packaged, static, read-only, **entirely synthetic** (An, Bình, Chi, Duyên or anonymous fake IDs). Reject arbitrary file paths, URLs, raw photos, external avatars or imported real TikTok records. Do not persist raw normalized user keys to public logs. Avoid unsafe HTML insertion; continue using escaped `textContent`/existing overlay.
- **Deterministic virtual clock** and sorted total order: given fixture + seed + `atMs`, output same `Snapshot/Effects` and rendered actor/camera results. A pure replay engine must support monotonic `update(atMs)` like current `SliceDriver`, with script events consumed once and state progression in one owning engine; no second scheduler, repeated actor creation or wall-clock nondeterminism in event identity. Keep bounded memory / event limits / typed validation.
- Preserve gift semantics: `progress` is provisional, `final` is counted once, stable stream event IDs and streak IDs, duplicate/reordered/reconnect handling, invalid/stale-room epoch rejection, gift progression without fake confirmed counts; A→B→C FIFO between distinct real givers, Duyên at 4th/no-seat gets only truthful text-only acknowledgment. Session disconnect and reconnect must not replay old pending gift or re-bind the wrong actor. New room cancels stale scope.
- Any input schema you introduce must be **versioned** (e.g., `offlineReplaySchemaVersion:1`) with declared limits, explicit local fixture copyright/provenance as original synthetic data. No claim of compatibility with any specific commercial provider payload without inspecting that provider's actual API or supported connection.

## 3. Phased implementation/gates

### Phase A — exact source audit and minimal replay seam
1. Codex verifies pinned PR #14 HEAD, scope of open stacked dependencies and reads Rules/Design 25, inspected `protocol.ts` `DemoEngine`, `SliceDriver`, event and viewer tests. Establish baseline **8 Event +39 Viewer =47 tests** as reported in PR #14 logs, and two builds. Store full known old `P014.md` native screenshots/7-shot info and GLB hashes; do not rerun Blender or invent GPU results.
2. Design the smallest shared `update(atMs)` return shape matching existing use in `main.ts` (state, actor, active, overlay) without changing the authoritative Event Engine semantics. Extract helper(s) only if necessary and preserve `SceneObserver` exact protocol-version/revision/time rejection. Keep future live transport separated from this offline bridge.

### Phase B — synthetic packet decoding, replay and viewer feature gate
1. Implement strict synthetic packet schema, stable normalization to typed `DemoEvent|SessionEvent` for member/chat/like/room/gift and session open/disconnect/reconnect. Reject malformed JSON/unknown type, oversize packet (> bounded configured byte limit), invalid IDs/counts, invalid viewer name/URL, unordered negative time or room scope manipulation. Parse unknown before ingest; stage telemetry with disposition, not secrets.
2. Provide **at least two complete original synthetic streams**, seeds 9/71: 85-second idle/no gift; 66-second member/community/gift lifecycle with observed streak, final once, duplicates/reconnect, A→B→C, capacity D/no-seat, new room, overflow-like/malformed packet and stable viewer count updates. Sort correctly; use `atMs` and `connection` as event protocol expects.
3. Implement a development-only replay selectable in Viewer via `?source=replay&fixture=<allowlisted ID>` or a single fixed fixture. No uncontrolled user-provided URL/path and **no network listening**. Existing `?demo=community` behavior remains byte/scene identical without `source=replay`. In replay mode `?botanicals=on&diversity=on&blessing=on` may render those already-approved effects but must not enable any real provider source or viewer count beyond three live DEMO seats.
4. Reuse existing SceneObserver/giftFx binding; verify avatar name anchors, female P05f + male P07b1, actor seat target, anonymous decorative figures and no-seat fallback. Do not rewrite camera routes or renderer glow.

### Phase C — tests, evidence and security
1. Run original 47 tests and both builds, plus dedicated integration tests for protocol version, unknown input, strict counts, buffer/JSON length, duplicate events and streaks, repeated `final` with new ID, reconnect connection++, room epoch reset, out-of-order/stale, cross-room collision, no-seat/queue-full, request TTL, malicious displayName, URL injection, memory cap and reload equivalence; snapshot parity between replay and an equivalent directly ingested event fixture. Test production build refuses replay mode; test no external network calls from replay fixture path.
2. Genuine native **720×1280 ECO/QUALITY browser WebGL screenshots**: start/scene, An arrival, progress, confirmed and blessing, B/C FIFO, D/no-seat, disconnect/reconnect, room reset and cinematic return (at least **six** distinct actual 3D cameras/shots per profile). Provide original screenshot SHA and replay input checksum. Include 85s idle and ≥66s stream in virtual time, three seeds 9/71/1337 for sensitive camera paths.
3. Browser resource/context restore and Event Engine disconnect/reconnect tests must not leak actors, replay stale gifts, display raw HTML or lose gift focus. Same-host frame cost relative to `source=demo` **only if measured**. If no physical RTX, report SWIFTShader software only, `P10A_HARDWARE_EVIDENCE_PENDING`; no 30fps/VRAM claim.
4. Full provenance: exact base/new HEAD, allowed code changes and tests, fixture 100% fictional, zero-cost, no remote transport/auth, no actual TikTok/LIVE Studio, `P014_FULL_REFERENCE_FIDELITY_PARTIAL` unchanged. Legacy screenshot parity when replay switch absent.
